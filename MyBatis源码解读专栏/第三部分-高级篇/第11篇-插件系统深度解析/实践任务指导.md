# 第11篇：实践任务指导（插件系统）

本实践以“可观察性 + 行为变更”两类插件为主线，帮助你把插件系统跑通并具备调试能力。

## 必做任务 1：耗时统计插件（推荐）

### 目标

- 拦截 `Executor.query(...)` 与 `Executor.update(...)`
- 统计耗时，超过阈值输出一条慢 SQL 日志

### 步骤

1. 创建插件类 `SqlCostInterceptor`（参考 [代码示例集合.md](./代码示例集合.md)）
2. 在 `mybatis-config.xml` 的 `<plugins>` 节点注册插件，并配置 `slowMs`
3. 运行任意查询用例，观察慢日志输出

### 调试建议

- 给 `org.apache.ibatis.plugin.Plugin#invoke` 打断点，观察签名匹配是否命中
- 给你的 `intercept()` 打断点，观察 `invocation.getTarget()` 是不是代理对象
- 观察多个插件叠加时的执行顺序（外层代理先执行）

## 必做任务 2：逻辑分页插件（RowBounds）

### 目标

- 拦截 `Executor.query(...)`
- 当 `RowBounds` 非默认值时，返回分页后的子列表

### 步骤

1. 创建插件类 `InMemoryPagingInterceptor`（参考 [代码示例集合.md](./代码示例集合.md)）
2. 配置到 `<plugins>` 中
3. 在任意查询调用中传入 `RowBounds(offset, limit)`，验证返回列表大小与预期一致

### 注意

- 该方式是逻辑分页，数据量大时会有明显性能问题，仅用于学习插件“改变行为”的能力

## 选做任务：理解物理分页的实现思路

### 目标

- 了解常见分页插件为什么会拦截 `StatementHandler.prepare(...)`
- 了解 `BoundSql.sql` 是 `final` 字段，改 SQL 需要反射/MetaObject 的原因与风险

### 练习建议

- 阅读 `org.apache.ibatis.mapping.BoundSql` 的实现，确认 `sql` 字段不可直接 set
- 思考：如果要支持多数据库方言，你会把方言选择逻辑放在哪里？（插件配置 / 环境变量 / 数据库元信息）
